# maps 统一存储迁移（2026-10-22）

用户最终决定：作品以磁盘为准，视频、谱面 JSON、曲绘及发布状态保存在 maps；不能依赖浏览器曲库才能重开作品。本次替代原“IndexedDB 作品 + 只读 maps 曲包”架构。

## 目录与保存

每首歌的 MP4 与 project.json、wfp-dance-draft.json / wfp-fitness-draft.json、wfp-dance-released.json / wfp-fitness-released.json 同目录。project.json 记录关联、各类型草稿／发布文件、专辑和更新时间；谱面文件仍为原 Chart JSON，供检查、备份和外部编辑。曲绘写入同目录，专辑设置保存在 maps/library.json。未发布的空谱也能保存。进入创作后最近作品指针只是浏览器偏好，缺失时可从磁盘草稿恢复。

保存和发布经本地服务写盘，成功响应之后才显示已保存。JSON 临时文件写完后替换，上一版 JSON 在同曲目 .wfp-backup 目录保留；同目录 .wfp-save.json 保存待完成的 JSON 事务，成功后移除，中断后下次读取时完成。不改写原视频，也不自动删除原导入谱面。草稿与发布快照继续独立，曲绘按内容生成不可变文件，避免改草稿曲绘污染发布版。撤下和删除状态也写入 maps，删除作品不删除原文件。存在外部修改或另一窗口保存时拒绝陈旧版本覆盖。

maps 内已有视频按大小、毫秒修改时间唯一匹配并直接采用，不复制整段视频；外部视频只在导入时流式复制一次。关联 ID 与文件名分离；MP4 改名后在曲目文件夹内按已记录的大小／时间唯一恢复，多个候选不猜测。播放继续使用 HTTP Range，不把整段 MP4 读入内存。迁移和普通保存不做视频转码或额外绘制预热。

## 旧作品与兼容

首次使用新版页面时，应用通过正常曲库加载读取当前 origin 的旧 IndexedDB。能匹配 maps 视频的作品直接迁入视频所在目录；已有磁盘作品优先。服务器重新读回落盘文件，且原浏览器 Song JSON 已写入该曲目 .wfp-backup/browser-内容摘要.json 后，不清理浏览器原始作品、专辑或视频缓存／句柄；用户检查确认后再另行清理。未迁入的作品保留可见并提示重新定位，不清除失败记录。新作品不再写入浏览器作品库或视频库。不会从工具读取用户当前正在编谱页面或强制刷新该页。

旧 song.json 曲包与仅有 .wfp.json 的目录继续读取；在应用中编辑后产生 project.json 和托管谱面，不覆盖作者原始 JSON。project.json 存在时以其引用为准，避免多个旧文件被当成重复谱面。导出分享 ZIP 的接口保留，仍只包含发布快照。

纯静态 dist 无本地保存服务时必须明确报错，不能退回浏览器保存并假称已写盘。旧 origin 的浏览器数据仍需在该 origin 打开一次新版应用才能迁移；新浏览器不能凭空读到另一浏览器尚未迁出的记录。
