# Fitness：歌曲结构驱动编排要求

2026-10-23，用户明确补充。状态：**需求已确认，尚未实现**。现有 v2 的局部节奏／动态边界算法不满足本要求，不能描述为已经识别曲式的模型。

## 用户确认的核心目标

生成器必须能够分辨 intro、人声入场、Aメロ、Bメロ、副歌及其他常见音乐结构。动作组的选择、开始／结束、重复／镜像，以及激烈程度，应与这些结构及音乐发展紧密关联。这原本就应纳入人工优质 Fitness 谱面的学习范围，不能仅提取动作序列和全曲轨道占比。

此前统一算法、无需用户选择运动强度的要求保留；它不意味着全曲采用同样动作密度或同样激烈程度。现有 `medium` 元数据也不能代替段落负荷规划。

## 当前实现事实与缺失

`structure.ts` 比较候选边界前后各两小节的起音／能量特征，没有明确变化时沿八小节框架推进；开头是短引子的启发式判断。2026-10-28 移除弱证据的七／九小节漂移，增加拍级安静／回落留白、轻动态约束、降低轨道配额的权重，并删除按段落序号轮转恢复；报告中的动作组不再称作音乐段落。这些仍是规则修正，未接入曲式语义模型，不能视为本需求完成。

尚无曲式语义分类、唱段／人声活动检测、旋律／和声描述或段落功能学习。三首人工谱的既有学习成果主要是动作积木与部分节奏／能量关联，不能据此声称理解 intro、A／Bメロ或副歌。修正固定延后与前置空拍，不等于补齐这一能力。

## 设计方向（待真实音轨验证，不是已学得的规则）

分析需要区分三个层次：

1. **歌曲结构与事件**：段落起止、功能标签、相似／重复段落组，以及独立的人声入场／退出事件。人声入场不是与 intro 或 Aメロ互斥的段落标签，不用“第一次有人声”直接替代主歌起点。
2. **运动编排计划**：每段采用什么动作组合、维持多久、何时变化／镜像／休息，如何逐步增加、释放和回收负荷。
3. **具体落谱**：按拍点铺入完整积木，处理左右对称、起身／落脚回位、长条与段落边界。结构未验证时，不能用落谱正确代替曲式识别正确。

建议标签范围覆盖 intro、Aメロ／主歌、Bメロ／副歌前过渡、chorus／副歌、post-chorus、instrumental／间奏、solo、bridge／独立桥段、breakdown、outro，并允许 unknown。标签不能强行固定顺序；Bメロ与 bridge 不机械等同。适用性、命名和更细的层次需在项目实际歌曲上核对。

段落至少记录：起止时间与小节、标签、重复组、依据与不确定性；人声事件单独记录时间与证据。优先保留可核查的不确定结果，不给每个八小节窗口强贴名称。

## 应重新学习的音乐—动作关系

在三首人工参考中对照音乐段落与实际动作，逐项标注和归纳：

- 首组动作与 intro、人声入场、主歌／器乐进入的关系，保留人工选择的准备和休息空间。
- 主歌内如何建立稳定循环，过渡段是否递进，副歌采用哪些标志组合，第一／第二／最后副歌是否相同或变化。
- 同段落重复时，动作是原样重复、左右镜像、局部替换，还是递进；不能仅因音频相似就强制相同动作。
- 间奏、桥段、breakdown、outro 如何换部位、恢复或收束。具体负荷必须看参考证据，不预设“桥段一律休息、最后副歌一律最强”。
- 动作激烈程度综合动作类别、频率、保持时长、双轨配合、累计负荷与恢复安排；不把音量大小等同于运动强度。Side Crunch 稀有、左右对称等用户要求继续保留。

这些是待学习的问题清单，不能作为已经由三首样本证实的规律。

## 验证顺序与交付标准

先给出三首参考曲和极乐净土／愛スクリ～ム的可核对结构时间轴，分别检查段落边界、标签、人声事件和重复组，记录每首的错误；边界误差要用拍／小节与秒同时表示。仅有动作 JSON 的现有参考尚未含人工曲式标签，不能把自动预测反过来当作人工标准。

结构验证后再学习段落功能与动作负荷的对应关系，输出可解释的段落编排计划，最后生成独立命名草稿供检查。原人工谱、用户修订稿与已发布版本保留。

需要覆盖安静副歌、没有人声的歌曲、直接从副歌起、短视频剪辑、重复副歌、明显器乐段、渐强与快速编曲变化等情况；不要求每首曲子具备所有标签。不沿用“八小节划对”作为曲式识别验收。

分析在生成阶段运行，结果可持久保存在同曲 maps 项目中并按音频／分析版本失效，游玩时只读取结果。模型体积、Windows 本地依赖、耗时、内存及其他设备支持均应实测后说明，不能先承诺零开销、即时完成或全曲准确识别。本轮未安装模型、下载权重或修改生成逻辑。

## 已核对的候选资料

- [All-In-One 官方仓库](https://github.com/mir-aidj/all-in-one) 提供拍／小节强拍、功能段落边界及 intro／verse／chorus／bridge／outro 等标签。只是候选，不代表能直接满足本项目的人声事件、Bメロ区分与设备要求。
- [SongFormer 原论文](https://arxiv.org/abs/2510.02797) 研究段落边界与功能标签，公开模型／代码／数据；可作为另一候选评估，论文基准成绩不能替代本项目实际音轨核对。

结构模型评估与三首教练谱的编排学习是两项不同工作：已有动作样本有助于学习如何编排，不能自动提供通用歌曲结构识别能力。
