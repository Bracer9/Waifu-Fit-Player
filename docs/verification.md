## 本次 UX 修订验证

### 作品与视频一起打开

- 实际 MP4 经文件输入导入并存入本机缓存，保存 JSON 后刷新，再打开时无需重新选择视频，且能实际播放；谱面内容往返一致。
- 原生 FileSystemFileHandle 经 IndexedDB 保存、刷新和恢复；该路径只保存句柄，不复制视频。自动化使用浏览器 OPFS 中的真实文件句柄替代系统选择器，权限过期／拒绝／再次允许通过受控模拟覆盖；操作系统级文件选择器与授权弹窗仍需人工操作。
- 同名但 ID 不同的作品不借用当前视频；缺失关联要求重新定位。旧版谱面一次定位并重新保存后，下次可以自动恢复。
- 损坏 MP4、存储失败、取消新建、取消定位不替换当前工作区，也不开放无视频的编辑器；全屏中的定位窗口与错误提示可见。
- 恢复浏览器草稿同时恢复视频。成功打开另一个作品重置选择和录谱工具状态，避免沿用前一作品的录入状态。
- 暂停后紧接松键以媒体元素的即时 paused/seeking/ended 状态为准，避免等待 pause 事件时多录一个 TAP。
- 本次通过 34 项核心测试、13 项浏览器交互测试；生产构建与格式检查通过。整曲播放逻辑未修改，沿用首版完整播放结果。

### 前一轮跟练与编谱交互

- 跟练页不显示主导航、新建、打开谱面、更换视频、保存、导出或操作说明；返回工作台后恢复编辑入口，同一视频节点仍然连接，媒体位置与速度不变。
- 真实键盘事件录入短按 TAP、长按 HOLD、Ctrl + 长按 SWAY，`1～4` 立即切轨。0.5 倍速时长使用媒体时间，重复 keydown 不连刷，按住过程中切轨与释放 Ctrl 不改变当前音符的初始属性。
- 吸附后起止落在同一点的 HOLD 延伸到下一网格点；暂停或跳转取消未完成录入。
- “反向”按钮、F 快捷键、多选翻转及撤销，1↔2 与 3↔4 双向拖动，拒绝跨方向组；HOLD 时长与 SWAY 属性保留。
- 跟随默认锁定，编辑不取消跟随；播放滚动到播放线。焦点在锁按钮或已解锁的跟随复选框时，空格只控制播放／暂停，不切换锁或勾选状态；可以解锁、关闭、重新锁定。
- 截图检查 1280×720、1440×1000、1920×1080；跟练画面与播放控件完整显示，无页面横向或纵向溢出。编辑界面保留原有较矮窗口纵向滚动行为。
- 本次最终执行 `npm run check`、`npm run test:e2e:quick`、`npm run build`、`npm run format:check`。截图在 `artifacts/demo-player.png`、`artifacts/demo-editor.png` 和对应分辨率图片中。

## 限制与复现

- 自动化验证了 JSON 下载保存；原生“另存为”文件选择对话框及操作系统权限交互没有在自动化中覆盖。浏览器不支持原生保存接口时会回退为下载；也可始终使用“导出 JSON”。
- 完整歌曲验证使用当前目录中的素材。换其他编码的 MP4 仍需浏览器实际解码验证。
- 示例谱是功能演示，不代表视频中每一个动作都已人工对齐。
- 浏览器测试失败时会保留截图与 trace；通过测试的布局截图位于 `artifacts/`。这些运行产物不提交到 Git。

复现命令和操作说明见根目录 README。测试运行时不读取个人 Chrome 资料。开发服务器忽略浏览器报告和测试截图变化，避免生成报告时刷新用户工作区。
