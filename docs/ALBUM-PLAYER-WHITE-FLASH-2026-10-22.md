# 专辑播放器偶发空白调查 — 2026-10-22

## 用户报告与当前结论

用户在专辑页向下滚动到「流行」、选择并等待几秒后，看到粉色播放器部分区域大面积空白，或右下角短暂出现白色区域，很快恢复。发生条件和首次出现版本未知，目前未持续出现。

**后续用户截图已确认：整块粉色机身背景及其细线缺失，封面、白色文字、进度条、按钮和黑色插槽仍在。** 这与首轮修复的尺寸错位不同；本地尚未抓到同样的瞬时异常帧，不能承诺偶发问题已被完全排除。

## 再次复发与当前状态

用户随后要求静止对照：展开播放器期间，粉色机身固定为原来的 -33deg 朝向，不再随音乐平移／缩放，MusicPulse 同时停止向这个节点写入律动变量；收起后恢复角落律动。下落与轮廓展开仍使用原时长，封面动画、青色角落及其他控件不变。本轮不启动额外浏览器测试，仅构建交付供实际观察，不能预先声称解决闪白。

用户明确确认刷新后仍然出现，并补充白色区域像是在侵入画面。第二张截图还显示「动漫」卡片的名称、数量等文字缺失，图片和卡片边框仍在。因此，不能继续将问题限定为粉色背景本身；替换大阴影没有解决根因。

只读检查用户现有 Chrome 页（未点击、刷新或切歌）：加载的是 `index-5TGyItLF.js`，实际 CSS 视口 2048×1096、devicePixelRatio 1.25。粉色节点与填充节点均为可见、opacity 1，动漫卡片文字仍在 DOM，页面无已捕获的 warn/error；读取时画面已恢复正常，没有捕捉到异常同时的样式。实际使用的专辑效果包含 all-record、sunset-window、idol-stage、vinyl、moon-right。

隔离复测匹配了该视口、密度、三张作者封面和两首流行试听，在约 43 秒场景中抽查九次粉色背景与动漫文字像素，未捕捉异常。**用户随后指出，复测期间其真实窗口多次长时间严重异常，而我没有观察到。隔离截图的通过不能代表用户实际窗口正常，也不能排除测试负载加重异常。** 已停止浏览器测试和截图采样，核对没有 4180 测试服务、测试 Node 或 Playwright 专用 Chrome 主进程残留。不得在用户运行游戏时继续反复启动并行测试窗口。

第二次修正改为 `AlbumHousing.tsx` 直接绘制实心 SVG 多边形，用 SVG points 在 620ms 内插值，复用原下落、音乐 transform 和同一组轮廓坐标；中断时从当前 animatedPoints 继续。背景本身不再经过 CSS clip-path 或大面积扩展填充，裁切仅保留在装饰细线与网点容器上。封面 aperture 加 `isolation: isolate`，将 screen 灯光混合限制在封面内。普通编辑器的原背景保留；减少动态效果及 resize 时直接归位。

该修正旨在移除可疑绘制依赖，**不是已经证实的底层故障解释**。212 项单元测试、类型检查通过；此后没有再次启动浏览器复测，SVG 展开、视觉一致性及瞬时白块是否消失尚未完成运行验证。不得将先前的浏览器通过结果算作第二次修正的验证。

## 已确认并修复的尺寸问题

- 路径：1470×956 小窗口，编辑器 → 顶部「音游模式」直接进入专辑页 → 选择流行、展开播放器。
- 编辑器使用实际窗口坐标，菜单则缩放 1920×1080 的逻辑舞台。`AlbumDeck` 的子组件 layout effect 可能早于 App 的视口模式切换执行，读取到编辑器模式的 1470×956，却将结果应用到 1920×1080 逻辑尺寸的机身，造成轮廓和白色细线错位。
- 修改前读取到机身宽高约 691×1404，但裁切起点为 `456.577px 5.137px`；正确的 1920×1080 机身裁切起点应为 `536.639px -10.977px`。1920×1080 窗口没有这项坐标差异。
- `src/components/AlbumDeck.tsx` 现显式使用菜单模式的 `fitMenuViewport(innerWidth, innerHeight)`，不再依赖尚未更新的全局模式。保留原机身、音乐律动、色彩和展开动画。
- `tests/menu-viewport.spec.ts` 增加编辑器直接进入专辑页的回归，检查首次展开前的逻辑轮廓，以及切到较大窗口后的轮廓一致性。

- 近日的确认页转场在另一页面使用独立图层，本轮没有发现它在专辑页停留时运行的证据。

## 收到截图后的背景绘制修正

- `album-deck.css` 移除粉色机身的 50vw 实心 box-shadow，使用 `App.tsx` 中的 `.album-housing-fill` 实色色块补齐背景。色块位于轮廓和网点下面，与原角落共用已有裁切、展开和音乐变换，不替换播放器布局。
- `albumHousingOutline` 根据闭合矩形及展开多边形顶点的联合边界计算 `paintInset`，多留 2px；`AlbumDeck` 仅在进入菜单／窗口变化时写入该范围。不引入逐帧计算、模糊、额外阴影或强制 GPU 常驻图层。
- 在 1920×1080 的逻辑舞台，补齐色块约为 1188×1494，而原阴影名义外扩包围矩形约为 2611×3324。两者都是几何范围比较，**不是已测量的显存占用或浏览器实际纹理分配**。
- 这项改动移除了最可疑的大阴影＋裁切绘制组合，但未取得异常发生时的浏览器 trace，尚不能证明底层具体失效原因。
- `tests/album-housing.spec.ts` 在 2557×1427 与 1470×956 两种窗口，检查不同音乐变换强度下实际截图的右侧背景像素（粉色比例须超过 98%），并验证收起／再次展开；另跑原音频回归覆盖实际试听、暂停、随机换曲和插入。3 项浏览器场景、212 项单测和类型检查通过，已人工查看两种尺寸截图。
