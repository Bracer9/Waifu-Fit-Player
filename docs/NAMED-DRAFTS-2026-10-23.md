# 命名多草稿与打开流程修复

## 使用方式

- 工作台点「保存草稿」或 Ctrl+S，直接覆盖当前草稿，不询问名称；当前为命名版本时更新该版本，未命名时保存当前工作副本。
- 右上角保存按钮旁的箭头打开菜单，选择「另存为…」才输入名称。不同名称新增一份，同一歌曲、同一谱面类型下的同名保存更新原份，名称不跨 Fitness／Dance 混用。当前已命名时，默认建议「原名称 副本」。
- 「本地作品」中每首歌的 Fitness／Dance 行各有草稿下拉框，选中后点「继续草稿」；「当前草稿（自动保存）」仍可继续最近的编辑状态。
- 自动暂存保留当前编辑状态，**不会悄悄更新已经命名的版本**。普通保存才覆盖当前命名版本；直接另存修订版则保留初版，不先覆盖初版。
- 切换到其他命名版本时，当前修改若尚未保存为任何命名版本，会先保留为「未命名草稿」副本，再加载选中版本。
- 旧单草稿直接作为当前自动保存草稿使用，不要求迁移。发布仍只替换当前类型的发布快照，其他草稿／发布版保留。

## 磁盘格式与保护

`Song.namedDrafts` 保存 `{id,name,chartType,chart,cover,albumId,updatedAt}`，`activeDrafts` 记录当前工作副本所基于的命名版本。原 `drafts.fitness/dance` 继续作为当前工作副本，保持原发布、自动生成和试玩流程兼容。

每份命名草稿直接存放在歌曲的 maps 文件夹内，文件名为 `wfp-<fitness|dance>-draft-<UUID>.json`，与 MP4 同目录。人读的名称保存在 `project.json` 的命名草稿清单中，不把名称作为文件路径；斜杠等显示字符不会变成路径。没有新增浏览器谱面存储或复制视频。

所有草稿与当前工作副本沿用原保存事务日志和 `.wfp-backup`。命名文件也参与 revision 哈希，外部修改任一草稿都会触发写入冲突保护；路径、UUID、类型、名称和重名输入先校验，再落谱面 JSON。旧客户端未带命名字段时，服务端保留原命名草稿，不将字段缺失当作删除。

本次未新增命名草稿的删除／独立重命名操作；改名保存是另存，已有名称保留。分享 ZIP 仍只导出发布版本，完整作品目录复制则包含全部草稿。

## 极乐净土的打开错误

旧页面的曲库与写入版本记录一直复用内存数据。磁盘安装 v2 后，旧页面试图按原 revision 打开并重新关联视频，触发“磁盘谱面已被修改”；错误又被统一包装成“定位作品的视频”，造成视频丢失的误导。

已确认视频可正常读取，实时 5173 返回344动作、有效视频地址，HEAD 200。先用独立新页面在现有正式版打开实际曲目并启动播放，视频时间前进到3秒以上、无页面异常，截图核对通过。用户当时正在使用的页面与服务没有被停止或自动刷新。

源码中的长期修复：打开本地作品前先完成必要的本地保存，再串行重扫磁盘。新的歌曲数据与对应 revision 一起更新，不能只换 revision 然后把旧工作内容写回去；磁盘版本已变时锁住旧工作副本自动保存，重新打开后恢复。版本冲突改为返回本地作品选择，不再要求重新选视频。选定版本在保存当前状态后从最新曲库快照取得，避免回载旧闭包对象。
