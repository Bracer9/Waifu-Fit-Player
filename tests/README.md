# 测试维护

日常先运行 `npm run check`。按改动选择浏览器 spec；需要整体冒烟时运行 `npm run test:e2e:quick`。常规功能、视觉、性能、整首播放和曲包有独立入口，见根 README。不要为文案、排序等小改动默认跑完整组。

## 素材与隔离

- `fixtures/player/demo.mp4`：60 秒、1920×1080、30 fps，合成色块与低音量音轨。普通谱面由 helper 限定在素材范围内；有特殊时序的测试传入自己的小谱面。
- `fixtures/player/endurance.mp4`：267 秒，同样的编码与合成内容，用于压力及整首播放。它不是实际舞蹈视频解码负载的替代品。
- 两者均无个人素材，通过 `npm run test:fixtures` 重建；只在重建时需要 ffmpeg。BPM 检测继续使用原有专用节奏素材。
- `scripts/test-server.mjs` 仅用于测试：在 4180 覆盖 demo HTTP 路径，复用 Vite 的文件／Range 服务。不会改写 public 演示视频、读取用户曲包或启动 predev。
- 不复用现有服务，不连接个人浏览器。全局清理向本次服务发出关闭请求，避免 Windows 测试进程退出时等待强制结束服务。曲包专项独立 4178。

## 2026-10-21 整理记录

原 `app.spec.ts` 的 19 个综合场景拆成媒体播放、媒体导入、编辑、录谱、STEP 创作和播放器特效 6 个文件；共享初始化与编辑操作在 `helpers/editor.ts`。空编辑器直接导入空谱，不再先导入整首、进入游戏、返回编辑器、导出再导入。

保留 18 个场景。删除的 1 个 STEP TAP／HOLD／SWAY 录入场景与五轨录谱、用脚颜色录谱重复；它独有的拒绝上方向操作已移入 `step-authoring.spec.ts` 的组合键场景。保存与恢复、旧谱迁移、非法输入、取消、失焦、撤销等覆盖均保留。

旧测试操作还统一更新为当前暂停菜单的 EDIT IN STUDIO，不再查找已移除的 WORKBENCH 按钮；绘制 helper 按目标时间点滚动，而不是把整条长时间轴居中。STEP 组合键用例中 ARMS 的 Shift+← 期待值修正为已经确认并实现的 ↖，没有改动录谱行为。

视觉细节以视觉专项及对应交互专项验收。拆出文件中 20 处重复成功截图已移除，失败截图／trace 保留；总截图调用从 167 降至 147。截图仅作人工检查证据，不能因为写出了 PNG 就宣称视觉验收通过。

25 秒 BGM 恢复故障回归保留在性能／长期运行组；整首播放单独标记 `@endurance`。固定延时只有确实验证按住、暂停或长时间恢复时才保留；普通等待优先使用可观察状态。

排序契约由明确预期的界面用例覆盖；其他绘制通过动作 ID 查行。变更测试期待值前，先核对用户需求和实现，不以让测试通过为唯一依据。不按测试年龄删除旧格式兼容或数据保护测试。

本轮验证结果在 `docs/HANDOFF.md` 的测试整理记录中维护。

2026-10-22 存储改造后，常规测试的 maps 按测试运行 token 和隔离浏览器上下文存放在 artifacts/test-maps；浏览器测试间不共享磁盘作品。helpers/library.ts 通过本地保存 API 注入作品，helpers/project.ts 的 lastDraft 从 maps 读取。仅旧版迁移用例继续向 IndexedDB 写种子；不要用读取旧浏览器数据库来断言新作品是否保存。maps-storage.spec.ts 覆盖新浏览器直接读盘和旧作品迁移后保留浏览器原记录；maps-workspace.test.ts 验证文件落点、改名、备份、冲突和中断恢复。相关验证不读写用户真实 maps，也不接管个人浏览器。
